Витрина APT для cairn

Репозиторий, из которого ставится cairn. Порождается задачей выпуска в закрытом репозитории кода; правки руками теряются при следующем выпуске.

Подключить

Один файл, /etc/apt/sources.list.d/cairn.sources. Ключ вкладывается прямо в него — отдельный keyring не нужен. Скопируйте целиком:

sudo tee /etc/apt/sources.list.d/cairn.sources >/dev/null <<EOF
Types: deb
URIs: https://p2bid.github.io/cairn-apt
Suites: $(. /etc/os-release; echo "$VERSION_CODENAME")
Components: main
Signed-By:
$(curl -fsSL https://p2bid.github.io/cairn-apt/cairn.asc | sed -e 's/^/ /' -e 's/^ $/ ./')
EOF

Дальше — две команды, и вторая обязательно от себя, а не от root:

sudo apt update && sudo apt install cairn
cairn install
cairn install не вызывается установкой пакета намеренно: он раскладывает уровень (skills и агентов) в домашний каталог человека, а скрипт пакета работает от root, где этого каталога нет.

Что здесь лежит

путьчто это
dists/<suite>/подписанные индексы по выпускам Ubuntu
pool/сами пакеты
cairn.ascоткрытый ключ, которым подписаны индексы
conf/, db/состояние reprepro, переписывается выкладкой

Кто предпочитает ключ отдельным файлом — кладёт cairn.asc в /etc/apt/keyrings/ правами 644 (файл читает системный пользователь _apt) и пишет Signed-By: /etc/apt/keyrings/cairn.asc.

Чего здесь нет

Архитектура одна — amd64. ARM не собирается и в индексе не объявлен.

Кодовое имя берётся разбором /etc/os-release, а не командой lsb_release: последней в минимальной системе и в контейнере обычно нет, и строка вышла бы с пустым Suites:.

Выпуски Ubuntu появляются здесь по мере сборки. Если apt update прошёл, а пакет не нашёлся — под ваш выпуск он ещё не собран; посмотрите, какие suite есть, в dists/.

Двоичный файл виден всякому, кто знает этот адрес: репозиторий публичный, потому что из закрытого пакеты через apt не отдаются вовсе. Исходники cairn при этом остаются закрытыми.
